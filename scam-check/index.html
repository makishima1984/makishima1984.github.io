01

What works here

Paste or type English text; review exact keyword matches; inspect parsed URL hostnames; explore five sourced pattern explainers; build a verification checklist; download a text review without your message.

All processing is local JavaScript. There are no external scripts, analytics, accounts, browser storage or network lookups. Clear removes the current input and result from the page. Refresh resets it to a synthetic sample.

02

What it cannot establish

The rules cannot authenticate a sender, classify all scams, inspect attachments, listen to calls, read your inbox, inspect a transaction or check a live URL reputation list.

There is no trained model or validated probability score. Precision, recall, false positives and abstention performance have not been measured on an independently labelled dataset. Quotes, negation, ordinary payments, unfamiliar wording and other languages can defeat these rules.

03

Sources and proposed scope

Audience proposal: a person reviewing a message before responding. English only; educational guidance draws on US FTC sources. No local reporting service is connected.

The supplied baseline and completed research handoff propose pasted-message and URL triage. The handoff arrived during this build and was reviewed before completion. Choosing this small scenario does not replace the full idea.

04

URL checks are unavailable

Addresses are parsed locally and shown as plain text. No pasted address is opened or sent to a provider. Paths, queries, fragments and user information are omitted from the URL detail display.

Google documents Safe Browsing as a URL threat-list service for non-commercial use, with Web Risk for commercial uses. Neither is connected here. A URL lookup alone would not verify an entire conversation.
